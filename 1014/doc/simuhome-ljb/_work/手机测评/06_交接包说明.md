## 3 关键数字

```text
负载口径       一条 5 轮轨迹：prompt 逐轮 1088→1700 token，累计 prefill 6988，监督输出 149

基线（含 observe_home 那一跳）
  5 步合计 67.5 s，单轮平均 13.5 s，首轮冷启动 39.5 s

方案 A（先预置固定头 [system+用户话+observe_home调用+房间清单]，从下一步起算）
  预热 42.9 s（不计入）+ 计时 24.0 s = 66.9 s
  预热命中 1207/1208 token，第一步 TTFT 136 ms
  单轮平均 6.0 s

T1~T5 各一条（方案 A，同一台常驻服务）
  22 步计时合计 145.7 s，单轮平均 6.6 s（prefill 4.7 s + decode 1.9 s）
  五条样本第一步 TTFT 均为 137~149 ms
  预热成本 3.8~6.8 s/条 —— system 那 1069 token 被自动共享，其余仍需各算

结论
  方案 A 是测量口径，不是优化：总耗时 67.5 → 66.9 s，净省约 0.6~1 s
  单轮平均 13.5 → 6.6 s 是口径效应（最贵的一轮不计入）
  预置成本要真正摊薄，只能靠方案 B 的按家共享
```

## 4 怎么复现

```powershell
# 手机连 USB，起服务（1.5B，-t 4，-c 4096）
adb -s 7LPRYTBYU8NRY5SC shell "run-as com.termux /data/data/com.termux/files/home/scripts/termux-run.sh shell '<启动命令>'"

# 本机 8001-8100 在 Windows 保留端口区间内，8080 绑不上，统一用 18080
adb -s 7LPRYTBYU8NRY5SC forward tcp:18080 tcp:8080

# 基线
python tools/traj_replay.py --host http://127.0.0.1:18080 --sample sc_T1_001 --skip-rounds 0
# 方案 A
python tools/traj_replay.py --host http://127.0.0.1:18080 --sample sc_T1_001 --skip-rounds 1
```

脚本依赖两个仓库外路径：`D:\项目\autodl-tmp\...\D_dataset.jsonl` 与
`...\D0_templates\A_policy.md`；手机上需要 `~/models/qwen2.5-1.5b-instruct-q4_k_m.gguf`。
