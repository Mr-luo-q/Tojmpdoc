# midea_probe.py

## 职责

主动连到美的蓝牙温湿度计，把它的 GATT 服务与特征全部列出来，并把所有"可读"特征读一遍。
用来回答那条唯一的未知：它的数据到底能不能读出来。

## 输入

```text
--address   设备地址，默认 50:5E:3A:E9:93:2C（2026-10-14 在树莓派旁抓到的那台）
--timeout   连接超时秒数，默认 30
--window    整段等待窗口的秒数，默认 60（设备只在被唤醒时短暂广播，所以连不上会自动重试）
--interval  两次重试之间等多久，默认 8 秒
依赖        bleak（树莓派上已装 0.11.0）
```

## 输出

```text
连接结果（成功/失败原因）
服务数；每个服务一行（UUID + 描述，标准环境感知服务会标出来）
    每个特征一行（UUID + 属性，例如 read,notify,write）
可读特征逐个读出的原始十六进制；电量特征会顺手换算成百分比
读取失败的特征打印异常类型（例如需要加密、需要认证）
```

## 读取

设备的 GATT 表与可读特征的值。只用被动扫描之外的"主动连接"，不写任何特征、不配对。

## 写入

无。全程只读，不改设备状态，也不改它的配对关系。

## 不负责

不解析温湿度数值（那要等确认特征格式之后再写一个解析器）、不做配对/绑密钥、
不写 MQTT、不解密私有协议。

## 失败时返回什么

```text
连不上       每次重试都打印原因，窗口用完再退出码 1
           （常见：设备不在广播模式、被手机占用、距离太远）
个别特征读不了  打印异常，继续读下一个，整体仍算成功
```

## 判定口径（读完之后怎么下结论）

```text
有可读特征且多读几次数值在变      → 能接，按格式写解析即可
只有需加密/需认证的特征           → 要绑密钥，成本高一个量级
服务表是空的或连不上              → 只认自家 App，判定不值得做
```
