# probe_lan.py

## 职责

在局域网里探小米设备：往 `224.0.0.50:54321` 发 miIO 的固定 hello 包，支持 miIO 的设备会单播回应答，应答里带 device_id。

它回答的是一个选型问题：设备能不能本地直连。直连可行的话，控制就不必走小米云，延迟能从十几秒降到毫秒级。

## 输入

```text
命令行    无参数
时长      固定监听 6 秒
```

## 输出

```text
有应答    "有 N 台设备在局域网上应答：" 后跟 IP 与 device_id
无应答    "没有任何设备应答——这些设备都是纯云的，本地直连走不通。"
```

## 读取

UDP 组播/广播的应答。不读文件。

## 写入

只发一个发现包。不写任何设备状态。

## 判定细节

```text
发的是 21310020 + ffffffff×6，这是 miIO 发现协议的固定魔数
收包时筛两件事：长度 ≥ 32、前两字节是 21 31
device_id 取 data[8:12] 按大端读
```

## 不负责

不做端口扫描（那是 `probe_ap_deep.py`），不判断设备型号，不尝试与设备建立控制通道。它只回答"有没有设备在这个网段上应答"。

## 失败时返回什么

超时按正常情况处理：没有设备应答时返回 0 并打印结论。即使返回 0 也不能证明设备不支持 miIO，只能证明"当前网段够不到它"——本机的实测结论正是这一条（笔记本在校园网、设备在家里的另一张网）。
