# probe_ap_deep.py

## 职责

连上设备的配网热点后，把设备所在的局域网彻底探一遍，目标是判断"能不能绕开米家直接控制它"。

## 输入

```text
argv[1]   要扫的网段前缀（可选）
          不给则自动用本机所在的 192.168 网段
          给了可以扫别的网段，例如设备入网后扫家用网段
依赖      无第三方库，只用标准库
```

## 输出（七步依次打印）

```text
1  本机 IPv4 地址        判断设备网段
2  TCP 扫描 /24           扫 10 个 IoT 常用端口（80 443 81 8080 8443 54321 6668 9999 22 23），找活跃主机
3  miIO 发现              UDP 224.0.0.50:54321，小米系设备会回应
4  Tuya 发现              UDP 广播 6666 / 6667，涂鸦系设备会回应
5  SSDP M-SEARCH          239.255.255.250:1900，找 UPnP/局域网页
6  mDNS 服务枚举          224.0.0.251:5353
7  ARP 邻居表             看哪些主机真的应答过
```

## 读取

网络应答；ARP 表（走 `arp -a` 子进程）。

## 写入

只发探测包。不写任何设备状态，不改网络配置。

## 并发与时长

```text
TCP 扫描用 160 线程池，单端口超时 0.4 秒
/24 × 10 端口 = 2540 次连接尝试
UDP 类探测各自有固定等待窗口
```

## 不负责

不切网络（切换由 `switch_and_probe.ps1` 负责），不解析协议内容，不尝试登录或控制设备。

## 失败时返回什么

各探测互相独立，单步失败不影响后续步骤。整体以 0 退出，结论体现在"有没有应答"上（本项目实测：全部无应答，判定为不走米家控制走不通）。
