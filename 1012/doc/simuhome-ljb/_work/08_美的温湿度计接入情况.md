# 08：美的温湿度计接入情况

> 核对时间：2026-10-12
> 依据：本机实测（HA 沙盒日志、集成源码与内置映射、BLE 扫描）、
>      用户口述的设备状态（美的美居里显示"数据未同步，要连蓝牙或网关"）
> 事实分级：【已核对】= 有本机证据；【推断】= 由现象推得；【待确认】= 需要用户或设备侧确认

## 1 一句话结论

这台温湿度计【已核对】是**蓝牙或网关型**设备，自身没有联网能力。它的数据只在"就近读它"的那条链路上，
所以**在它身边放一个网关上云之前，HA 拿不到它的任何数据**——这件事不取决于我们这边的配置。

用户的目标是把它接进 HA。当前状态是：接不进来，原因是设备侧缺一个"替它上网"的东西。

## 3 为什么进不了 HA

```text
传统路子（数据上云，HA 从云拉）
  温湿度计 ──蓝牙/网关──► 美的云 ──► midea_auto_cloud ──► HA
              ↑
              这一步断着：它身边没有网关，手机也不在它旁边
  结果：云上只有设备登记，没有实时数据
        日志里 connected: False，Status 实体一直 unavailable

本地路子（HA 直接读蓝牙）
  HA ──?──► 温湿度计
  ? 这一段物理上不通：HA 在 Docker 的 Linux VM 里拿不到 Windows 蓝牙
  而且现在 PC 在学校、设备在家里，蓝牙本来也够不到
```

## 4 实际试过什么，结果如何

### 4.1 美的云方案（midea_auto_cloud）

```text
信息来源   finally new paper\10_04V2接入小米后设计方案\辅助调研文档\10_美的设备HA接入方案调研.md
选它的原因 调研文档的"首选"是官方 midea 集成，但它要求 HA >= 2026.8 且走局域网直连；
           本机 Docker Hub 不通（升不了镜像）、校园网有客户端隔离（本地直连也不通）；
           云方案是唯一不依赖局域网的

装机前核对  hacs.json 要求 HA >= 2024.11.0 —— 沙盒 2026.5.4 满足
           依赖 lupa>=2.0 —— pip dry-run 解析到 lupa-2.8-cp312-abi3-musllinux wheel，装得上

实测过程   集成拷进沙盒 → 重启 → 日志认出
           起 config flow → 提交账号密码（server=2 美的美居）→ 登录成功，无错误
           家庭只有一个：247760014"布鲁斯的家"
           select_homes → download（异步）→ 摘要"成功 0 个 / 跳过 1 个"
           confirm → 条目建成，state=loaded
           lupa 2.8 由 HA 自动装上

卡住的地方 两个问题叠加
           其一【已核对】上游缺 T0x54 的映射文件
                内置 device_mapping\ 47 个文件里没有它；
                下载下来的 plugin\T0x54_10008857.zip 是美的美居 App 的 UI 插件
                （weex.js + 图片 + 字体，plugin.json 写着"智有范旋钮"），不是设备协议；
                .storage\midea_auto_cloud\lua\ 里只有 bit.lua 与 cjson.lua，
                没有这台设备的 lua（对应"跳过 1 个"）
           其二【已核对】云侧没有数据
                Status update: {'connected': False}
                Device 温湿度计 (212305752896363) failed 3 consecutive polls
                → Status 实体的属性是空的，没有可访问字段列表

结论      登录、家庭、设备识别都成功，集成本身没问题；
          缺的是数据源。设备不上云，云方案就拿不到东西
```

### 4.2 BLE 直读

```text
为什么要试  HA 自己碰不到蓝牙，但本机 Windows 可以（音箱桥已经验证过这个模式）

实测        scan.py   15 秒 → 193 台设备，无温湿度计
           scan.py   20 秒 → 有名字的全是耳机 / 触控笔 / 共享单车
           watch.py  45 秒 → 272 台，全是匿名设备
           watch.py  45 秒（先建基线再守）→ 基线 167 台，之后只冒出手机与穿戴类

重要更正   这四轮"扫不到"不能说明它不广播。设备在家里、PC 在学校，
           蓝牙广播根本传不了这个距离（标称十几米，穿墙还衰减）。
           所以这条实测的结论只有一句：在当前位置无法验证。
```

## 6 以后要接它，三条路

```text
一  换一个能上云的温湿度计（成本最低）
    米家系：数据进米家云，已装的 xiaomi_home 集成直接导入，零新代码
           步骤：_work\ha\xiaomi_options.py 刷新设备清单 → 确认实体出现
    美的 Wi-Fi 型：用已经装好的 midea_auto_cloud，启用条目即可
           前提：它的设备类型在内置 47 个映射里

二  在家里放美的的网关（不改代码，但要买对型号）
    就是 App 提示里的那个网关。网关在设备旁边就近读它并上传云端，
    之后 midea_auto_cloud 就能拿到数据
    步骤：启用条目（一条 WS 命令或 UI 点一下）→ 重载 → 看实体

三  家里放一台常驻小主机做蓝牙读取桥（成本最高）
    需要：一台常驻机器 + 能解开它的蓝牙协议（可能是私有格式、可能要配对密钥）
    本项目的同类先例是 _work\bt_speaker\bridge.py，但那个只做音频播放，
    不需要解协议；这台要读传感数据，难度高一个量级
```
