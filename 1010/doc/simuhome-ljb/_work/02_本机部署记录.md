## 2 和 deploy\03 不一样的地方，以及为什么

1. **SimuHome 不在 `simuprocject\Simuhome_experiment`**，实际在 `D:\Simuhome\SimuHome`。
   仓库的一键脚本 `_tools\start_simuhome_stack.ps1` 把路径写死成仓库内相对路径，所以在这台机器上
   跑不通。按 AGENTS.md 的隔离要求没去改它，改用 `_work\start_sandbox.ps1` 指向实际位置。
2. **broker 用 amqtt，不是 Mosquitto**。本机 `registry-1.docker.io` 不通（拉不到 eclipse-mosquitto
   镜像），也没有原生 Mosquitto。这条路是仓库自己在 `_tools\mqtt\README.md` 里写的：
   PyPI 可用 → amqtt 可装。配置照搬该目录下实测过的 `probe_mqtt.py`（允许匿名、不校验主题），
   只把端口从 18830 换成正式的 1883。
   → 连带结果：**不需要** `broker\mosquitto.passwd`；发布器读不到凭据文件会自动匿名连接
   （日志里有一条 "未找到凭据文件…将匿名连接" 的 warning，属正常）。
3. **HA 用沙盒专用配置目录 `D:\homeassistant-sandbox`**，没有复用现有的 `D:\homeassistant`。
   原因：`D:\homeassistant\configuration.yaml` 里还留着旧 REST 方案的 simuhome 传感器和模板开关
   （`switch.simuhome_living_room_main_light` 等），MQTT discovery 生成的实体名会和它们撞名，
   HA 会给新实体加 `_2` 后缀，工具面和 e2e 用例都会对不上。新目录干净，且完全不动你现有的 HA。
4. **HA 镜像用本机已有的** `homeassistant/home-assistant:stable`，没走 compose 里写的 ghcr.io 地址
   （省一次 3 GB 拉取）。
5. **MCP 配置放在 `_work\mcp\config.yaml`**，没有往 `ha_mcp_universal\` 里写 `config.yaml`。
   配置里的相对路径以运行时的当前目录为基准，所以记忆、别名表、预约库都落在 `_work\mcp\data\`。

## 3 初始化是怎么自动完成的

`D:\homeassistant-sandbox` 是全新实例，正常要在浏览器里点引导。这里改成走 API：

- `_work\ha\onboard.py`：建 owner 账号（随机密码）→ 授权码换 access_token → 走完引导 →
  WebSocket 签发长期令牌。产物：`_secrets\ha_token.txt`（仓库脚本默认读的路径）、
  `_secrets\ha_sandbox_credentials.txt`（登录用户名/密码）。
- `_work\ha\add_mqtt.py`：用 REST 版 config flow 添加 MQTT 集成，broker 填 `host.docker.internal:1883`。

## 5 "实体改名"这一步不能省

HA 2026.5.4 的 MQTT discovery 不认 `object_id` 键，实体 id 由「区域 + 设备名 + 实体名」自动拼，
结果是一堆 `switch.on_off_light_on_off_light` 这种名字，同名还会加 `_2` / `_3`。
必须跑 `simuhome_mqtt_publisher\publisher\rename_entities.py` 才会变成 `switch.simuhome_*` 的规范名。
本次已跑：`{"renamed": 25, "dry_run": false}`。
