# watch.py

## 职责

边扫边看，只打印"新出现"的设备与命中温湿度计启发式的设备，用来在按设备按钮的那一刻抓到它。

与 `scan.py` 的分工：`scan.py` 是一次性全量快照（15 秒内 190 多台设备，噪声大）；`watch.py` 前 8 秒当基线，之后新出现的才报，输出能直接看懂。

## 输入

```text
argv[1]   守护时长（秒），默认 60
依赖      bleak
```

## 输出

```text
开头提示：现在去按按钮 / 取装电池
[新出现]     基线之后第一次出现的设备
[命中启发式] 名字含温度/湿度类片段，或广播里带 0x181a 环境感知服务
结尾：总共看到多少台
```

## 读取 / 写入

只读广播。不连接、不配对、不写任何设备，也不影响手机 App。

## 不负责

不解析温湿度数值，不做 GATT 连接，不判断设备是不是你要找的那台（要按 MAC 或名字人工确认）。

## 使用场景

很多 BLE 传感器只在状态变化或按键时才广播，所以正确用法是先运行它，再去动设备：

```powershell
python D:\项目\simuhome-ljb\_work\ble\watch.py 90
```

然后在 90 秒内按传感器上的按钮，或把电池取出再装回。如果它确实是广播型，会在那一瞬间出现在 `[新出现]` 里。

## 实测

2026-10-12 用 `scan.py` 扫过两轮（各 15 秒与 20 秒），都没扫到温湿度计，当时设备正被手机 App 连着。`watch.py` 是为关掉手机蓝牙后再抓一次准备的。

搬到树莓派时同样撞到 bleak 的版本差异（`discover(return_adv=True)` 在 0.11.0 上返回 list、`adv` 没有 rssi），两处都已按 `scan.py` 里同样的办法做了兼容：基线也改用 `detection_callback` 收集地址集合。
