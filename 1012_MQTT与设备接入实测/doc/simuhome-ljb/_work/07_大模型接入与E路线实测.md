## 3 过程中修的两个环境问题（根因，不是症状）

两个问题都出在本机 Python 环境，不在仓库代码里。

```text
问题一  ModuleNotFoundError: No module named 'openai'
  现象   测试脚本 import openai 就失败
  根因   PATH 上的 D:\Anaconda\python.exe 装了 mcp / dotenv / yaml，唯独没有 openai
  处置   装 openai 3.29.0（它的依赖里有 httpx2 2.13.1 与 httpcore2 2.13.1）

问题二  TypeError: process() takes no keyword arguments
  现象   模型已经调起来（日志里多次 CallToolRequest），
         但在读响应体时崩在 httpx2 的解码环节
  根因   httpx2 2.13.1 的 BrotliDecoder 调用
           self.decompressor.process(data, output_buffer_limit=...)
         而环境里的 Brotli 是 1.0.9，它的 process() 只接受位置参数
         （httpx2 把 brotli 当可选依赖，包里没有版本下限约束，所以不会被 pip 自动升级）
  处置   Brotli 1.0.9 → 1.2.0
  验证   升级前 process(b"", output_buffer_limit=1024) → TypeError
         升级后同一调用 → 正常返回
```

判断依据是 `httpx2\_decoders.py` 第 156~196 行的 `BrotliDecoder`：它先试 `decompressor.decompress`，取不到就用 `decompressor.process`，两条路径都按"支持 `output_buffer_limit`"来调用。所以这是库版本配套问题，改测试代码或改仓库代码都治不了。

中间过程记一笔：第一轮为了不往源目录写文件，改用进程环境变量注入（`load_dotenv` 默认不覆盖已存在变量，两者等价），跑通 12/12；随后按"按仓库里的要求来"改回 `.env`，并在清空全部环境变量的情况下复跑，仍然 12/12、退出码 0。两条路都验过，现在生效的是仓库口径那条。

写入方式说明：`.env` 的值无法用 `apply_patch` 写（那会把密钥原文留在对话记录里），因此这次是用脚本读 `config.txt` 再落盘，结构核对只打印变量名与值的长度。
