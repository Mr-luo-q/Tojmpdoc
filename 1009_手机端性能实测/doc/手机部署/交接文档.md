## 一、这台机器现在能做什么

```text
可以立即使用    CPU 推理，两个模型都已推到手机

                 NPU（APU 780）—— 能枚举到 4 个加速器，但 llama.cpp 用不上
```

### 日常用法

```bash
# 交互对话（1.5B，质量好）
llama-cli -m ~/models/qwen2.5-1.5b-instruct-q4_k_m.gguf -t 4 -c 2048

# 交互对话（0.6B，快一倍多）
llama-cli -m ~/models/Qwen3-0.6B-Q4_K_M.gguf -t 4 -c 2048

# 单次提问（答完退出，会打印速度）
llama-cli -m ~/models/Qwen3-0.6B-Q4_K_M.gguf -t 4 -c 2048 -n 128 -st -p "问题"
```

**千万别用 `-t 8`。** tg 会从 15 掉到 7.8，损失一半以上。这个坑很隐蔽，因为"用满 8 核"看起来才符合直觉。真实原因是这台机器有三个簇（4×A510 2.2GHz + 3×A715 3.2GHz + 1×A720 3.35GHz），线程跨簇迁移破坏访存局部性，而 tg 阶段是访存受限的。

### 一个影响性能的系统层限制

**推理时 CPU 被锁在硬件上限的 54~64%，且完全不动：**

```text
cpu0 小核   1400 / 2200 MHz = 64%
cpu4 中核   1800 / 3200 MHz = 56%
cpu7 大核   1800 / 3350 MHz = 54%

同时观测：电池温度 28~37°C（不热）  low_power=0（省电未开）
```

相关系统事实：`scaling_driver = mtk-cpufreq-hw`（MTK 硬件调频器）、`mi_thermald` 在跑、`persist.sys.power.default.powermode = enhance`（增强模式，非性能模式）。

`performance` governor 在可用列表里，但写 `scaling_governor` 需要 root，Termux 无 root，这条路封死。**可以试的**：设置 → 电池 → 切到性能模式。

## 四、几个必须记住的坑

**1. 装 APK 需要插 SIM 卡。** 国行 HyperOS 的「USB 安装」开关在无卡时点不开，会提示先插卡。这次就是为了这个临时插了一张移动卡。装完可以拔。

**2. 小米的 USB PID 是关键判据。** `VID_2717&PID_FF40` 是 MTP（没开 USB 调试），`PID_FF48` 才是 ADB。只看到 FF40 就去开发者选项把「USB 调试」重新开关一次再插拔线。

**3. `adb install -g` 会被拒。** `INSTALL_GRANT_RUNTIME_PERMISSIONS` 在小米上是受限权限，去掉 `-g`。

**4. Termux 里不要用 `/tmp`。** 用 `$TMPDIR`（默认 `/data/data/com.termux/files/usr/tmp`）。

**5. 往手机推脚本不要推 `/sdcard/Download`。** Termux 没存储权限，读不了（`Permission denied`）。走 `/data/local/tmp/` 再拷进 Termux 私有目录。而且 `adb push` 的目标必须写完整文件名——写成目录（结尾带 `/`）时文件名会被截断。

**6. 想在 Termux App 进程内（而不是 run-as 环境里）跑命令，用 `input text` 注入。** `RunCommandService` 走不通（需要 `com.termux.permission.RUN_COMMAND`，adb shell 拿不到）。注入时注意：`input text` 不能输入 `>`、`&` 这类 shell 重定向符号，会被拆坏；用 `| tee 文件` 代替。

**7. PowerShell 5.1 下的两个坑。** 中文 `.ps1` 必须存成 UTF-8 **with BOM**，否则报莫名其妙的语法错误；`-split "`r?`n"` 这种写法会因为反引号转义而破坏解析，要写成 `-split '\r?\n'`。

## 六、没做完的事

**llama.cpp 的 Vulkan 后端没有真正接到 Mali。** 包装上了，但它链接的是 Termux 那个只看 Mesa ICD 的桌面版 loader，枚举到的是 `llvmpipe`（软件实现）。要接 Mali 必须改用 Android NDK 交叉编译，让产物运行在正确的 namespace 里。

**没有实测 CPU 推理速度。** 模型还在电脑上（`C:\Users\18343\Downloads\` 下的那两个 gguf），没推到手机。这次的重点全放在 GPU/NPU 探测上。

**NPU 端到端未验证完。** 手工声明的 `ANeuralNetworksOperandType` ABI 没通过参数校验，四种布局、两种类型常量都返回 `ANEURALNETWORKS_BAD_DATA`。要修得装 Android NDK 拿真实头文件。

**大模型服务与 Home Assistant 都没部署。** 这次范围只到「Termux + llama.cpp + GPU/NPU 探测」。

**没测散热与热降频。** 上次华为那台热降频严重（22 t/s 掉到 5.56 t/s），这台的天玑 8300 表现未知。
