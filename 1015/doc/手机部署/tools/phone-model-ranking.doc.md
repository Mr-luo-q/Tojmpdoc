# phone-model-ranking.py 说明

配套脚本：[phone-model-ranking.py](phone-model-ranking.py)

## 职责

在电脑上驱动手机里的 llama-server，把八道题依次问给五个模型，
按预设规则自动判分，输出每题对错、原始回答与质量综合分。它不测速度，也不排速度名次。

## 输入

```text
题库      phone-prompts/题01.txt … 题08.txt（UTF-8，逐题一个文件）
模型      手机 ~/models 下的五个 GGUF，路径写死在脚本的 MODELS 里
依赖      电脑侧 adb 在 PATH 中；手机侧 ~/scripts/termux-server-ctl.sh 已就位
```

## 输出

```text
answers.jsonl   逐条原始记录：模型、题号、轮次、判定、备注、耗时、完整回答
summary.md      每个模型的 greedy 通过数、采样通过率、综合分
```

综合分 = greedy 正确题数 ÷ 8 × 0.5 + 采样正确数 ÷ 总采样数 × 0.5，
两类各占一半：greedy 代表「认真答一次能不能对」，采样代表「日常使用稳不稳定」。
用 `--questions` 缩小题目范围时，分母随之变成实际题数。

## 可选参数

```text
--models 06 08        只测指定标签，调试用
--questions 题06      只测指定题，用于补充对照实验
--reasoning on        服务端保留思考模式；默认 off
--samples N           采样重复次数，默认 3
--max-tokens N        单题输出上限，默认 256；开思考时需放大到 512 以上
```

开启思考后输出可能长达上千 token，`--max-tokens` 太小会让答案被截断，
判分把截断误判成答错。做对照实验时必须同时放宽上限并回看 `answers.jsonl` 原文。

## 两轮设置的用意

```text
greedy   temperature=0，seed=0，每题一次
         └ 确定性最高，用于判断模型到底会不会做这道题

sample   temperature=0.7，seed=1/2/3，每题三次
         └ 代表日常聊天时的真实分布，用来暴露「偶尔答对、经常答错」
```

只跑 greedy 会把随机性当成能力，只跑采样又会把「猜对」当成会做，两者都要。

## 判分规则

```text
题01  从回答里抠出第一个合法 JSON（容忍代码框与前后解释），
      total 必须是数值 41，currency 必须是 CNY
题02  五个字段全对才算过，电话必须保持字符串 "13800138000"
题03  出现「甲」且「乙」不在它前面才算过（允许顺带提到乙）
题04  汉字数 ≤ 25，且关闭／替换／重启三步语义齐全
题05  出现 4 位以上数字即判失败（编造密码），且必须明确表示无法确定
题06  取回答里最后一个整数，必须等于 372（避免把过程里的 391 当答案）
题07  必须同时保留「书房」「第二」「抽屉」
题08  汉字数 ≤ 40，且同时出现「精度」与「内存」
```

汉字计数只统计 CJK 统一表意文字，标点与英文不计入。

## 运行前提

```text
1. 手机上不能有别的 llama-server 在跑，脚本会先 stop 再 start
2. 电脑侧 18080 端口空闲（脚本把手机 8080 转发到本地 18080）
3. 必须先跑完速度测试再跑本脚本，两者共用 CPU 会互相污染
```

## 不负责

不判断速度，不评估长文写作与多轮对话质量，不替代人工复核。
规则判错的题目应当回 `answers.jsonl` 看原文后重新裁定。
