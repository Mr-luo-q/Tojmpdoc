# tools/md2html.py 说明文档

## 一、这个脚本解决什么问题

项目的两份说明文档（`README.md`、`部署总结.md`）是 Markdown 格式，手机上直接看体验很差：表格会串行、代码块不换行、没有目录。电脑上又没有 markdown 库可用（本机无网络，装不了），所以这个脚本用标准库手写了一个转换器。

生成的是**单文件 HTML**：样式全部内嵌，没有 JS、没有外部资源，手机浏览器打开即用，也不需要联网。

```text
输入                              处理                     输出
──────────────────────────────────────────────────────────────────────
README.md          ┐                                   ┌─ docs-readme.html
部署总结.md         ├──► md2html.py（纯标准库解析）──►  ├─ docs-summary.html
（Markdown）        ┘                                   └─ docs.html
                                                          （自动跳转页）
```

## 二、命令行用法

```powershell
python tools\md2html.py <项目目录> <HTML输出目录>
```

实际例子（本项目用的命令）：

```powershell
python tools\md2html.py . .docs-html
```

参数说明：

| 位置 | 含义 | 本项目取值 |
|---|---|---|
| argv[1] | 项目目录，脚本会在此找 `README.md` 和 `部署总结.md` | `.`（当前目录） |
| argv[2] | HTML 输出目录，不存在会自动创建 | `.docs-html` |

## 三、输出结果

三个文件，都写进 `argv[2]` 指定的目录：

| 文件名 | 内容 | 大小（实测） |
|---|---|---|
| `docs-readme.html` | 《使用说明》的网页版 | 29976 字节 |
| `docs-summary.html` | 《部署总结》的网页版 | 27019 字节 |
| `docs.html` | 入口页，用 `<meta refresh>` 自动跳到使用说明 | 285 字节 |

三个页面顶部有互相切换的导航栏，正文自带目录（标题数超过 3 个才生成），跟随系统深色模式，表格可横向滑动。

## 四、支持的 Markdown 语法

不是完整实现，只覆盖项目文档实际用到的部分：

```text
语法                        处理方式
──────────────────────────────────────────────────────────────
# ~ ######                  转 h1~h6，自动生成锚点 id 并收集进目录
围栏代码块（三反引号）        转 <pre><code>，右上角显示语言标签
| a | b |                   转 <table>，包在可横滑容器里
- item / 1. item            转 <ul> / <ol>
> 引用                      转 <blockquote>
**粗体** *斜体*             转 <strong> / <em>
`行内代码`                  转 <code>
[文字](链接)                转 <a href>
![alt](图片)                转 <img>
---                         转 <hr>
```

## 五、内部函数说明

### inline(text)

职责：处理**行内**标记，返回转义后的 HTML 片段。

输入：一段可能含 `代码`、`**粗体**`、`[链接](url)` 的纯文本
输出：对应的 HTML 字符串

处理顺序很关键，先做的是「把行内代码抽出来换成占位符」：

```text
原始：  用 `**` 表示加粗
         │
         ├─ stash()      把 `**` 抽走，原位留 \x000\x00
         │                （否则它会被后面的粗体正则当成标记）
         ├─ html.escape  转义 < > & 等字符
         ├─ 依次替换 图片 / 链接 / 粗体 / 斜体
         └─ unstash()    把 \x000\x00 还原成 <code>**</code>
```

这层设计是必要的：文档里有一句「`-no-cnv` 会报 `invalid argument`」，如果不先抽走行内代码，反引号内的内容可能被其他正则误伤。

### is_table_sep(line)

职责：判断一行是不是 Markdown 表格的**分隔行**（形如 `|---|---|`），用于确认「下一行是分隔行」从而认定当前行是表头。

返回：布尔值。

### split_row(line)

职责：把表格的一行按 `|` 拆成单元格列表，并去掉首尾多余的空竖线。

输入：`| 参数 | 建议值 |` → 输出：`['参数', '建议值']`

### convert(md)

职责：**核心函数**，把整篇 Markdown 逐行转成 HTML 正文，同时收集标题层级。

输入：Markdown 全文（字符串）
输出：`(HTML 正文, [(标题层级, 标题文本), ...])` 二元组

返回的第二个值专门给 `build_page` 用来渲染目录，这样目录和正文的锚点一定一致（两处用同一套规则生成 id）。

内部用一个游标 `i` 扫描所有行，按优先级依次判断：代码块 → 标题 → 分隔线 → 表格 → 引用 → 无序列表 → 有序列表 → 空行 → 普通段落。代码块和表格要先于普通段落判断，因为它们跨多行，需要一次性消费到结束。

内部的 `close_lists()` 负责在遇到非列表行时补上 `</ul>`/`</ol>`，保证标签配对；它用 `nonlocal` 修改外层的 `in_ul`、`in_ol` 状态。

### build_page(title, md_path, nav, active)

职责：读一个 Markdown 文件，产出完整可独立打开的单文件 HTML。

输入：页面标题、Markdown 路径、顶部导航项列表、当前页标记
输出：完整 HTML 字符串

它会调用 `convert()` 拿到正文和标题列表，标题数超过 3 个才生成目录（太少没必要）。所有样式来自模块级常量 `CSS`，在浅色和深色两套配色间用 `prefers-color-scheme` 自动切换。

### main()

职责：命令行入口。

读取 `argv[1]` 作为项目目录、`argv[2]` 作为输出目录，对 `README.md` 和 `部署总结.md` 各调一次 `build_page()`，最后写一个自动跳转的 `docs.html`。源文件不存在时跳过并打印提示，不报错中断。

## 六、修改脚本后必须同步的事

改完 `md2html.py` 要重新生成并推到手机，手机上浏览器才能看到新内容：

```powershell
# 1. 重新生成
python tools\md2html.py . .docs-html

# 2. 推到手机服务目录（这样浏览器能直接读）
adb push .docs-html\docs-readme.html /data/local/tmp/
adb shell "run-as com.termux cp /data/local/tmp/docs-readme.html \
  /data/data/com.termux/files/home/llama-android/ui/llama-b11146/"
```

三个 HTML 文件都要推，否则导航切换会 404。

## 七、已知限制

**不处理跨行的行内标记。** 转换是逐行进行的，所以 `**加粗**` 的起止标记必须写在同一行。文档里原本有一处 `**` 跨了两行，导致渲染出字面星号，已改成同一行内闭合。

**不支持嵌套列表和表格内的复杂格式。** 项目文档没用到，所以没实现。

**不支持 HTML 块内嵌。** Markdown 里直接写 HTML 会被转义显示。
