# 手机提速测试提示词集

本目录是 [操作手册](../手机小模型提速复现操作手册.md) 依赖的输入素材，全部为 UTF-8 文本。经文件推送而不是 `adb shell` 传参，避开 shell 编码破坏中文的问题。

```text
题01~题08.txt     质量验收题集，逐题单独执行并保存完整答案
问答.txt          chat 端点延迟测试用；含中文与确定性计算，便于核对答案
缓存512.txt       裸 completion 缓存实验的短前缀
缓存2048.txt      裸 completion 缓存实验的长前缀
```

题01～题08 对应主报告的质量验收表：01/02 考结构化输出，03/07 考事实保持，04/08 考长度与用词约束，05 考不确定时是否捏造，06 考算术。只有 01、02、05、06、07 有唯一确定答案，是硬门槛；03、04、08 需要人工读一遍再判定。

缓存文件由同一段背景文本重复构成，末尾追问固定在最后一行。

| 文件 | 背景重复 | 字符数 | 说明 |
|---|---:|---:|---|
| `缓存512.txt` | 2 | 448 | 按 Qwen 中文大致 1 token 对应 1~1.5 字符估算，约 300~450 token，偏短 |
| `缓存2048.txt` | 8 | 1720 | 同上，约 1150~1700 token，偏短 |

**重复次数是近似手段，不是 token 数保证**：中文的字符数、字节数和 token 数都不同比例，实际长度必须用服务的 `/tokenize` 端点测出后写进结果目录。若测得的长度离目标较远，按 `目标 token ÷ 实测 token × 当前重复次数` 取整调整重复次数，重新归档，不要把文件名里的数字当结论。想让 512 版更贴近目标，把重复次数从 2 调到 3；2048 版从 8 调到 12 左右。

缓存实验的使用方式：先用 `--cache off` 跑一组，再用 `--cache on` 跑一组，两组都从新启动的实验服务开始，第一轮作为填充、之后几轮才是有热前缀的请求。追问行始终不变，前面背景也不要改动，否则前缀缓存失效。

```bash
# 推送方式：整个目录推到中转目录，再拷进 Termux 私有目录
adb push phone-prompts /data/local/tmp/phone-prompts
adb shell run-as com.termux mkdir -p /data/data/com.termux/files/home/prompts
adb shell run-as com.termux cp /data/local/tmp/phone-prompts/问答.txt /data/data/com.termux/files/home/prompts/问答.txt
```

这些文件只是输入，不含任何设备实测结果。测试流程与判定门槛见操作手册。
