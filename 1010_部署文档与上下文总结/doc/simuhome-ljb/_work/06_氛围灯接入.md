# 06：氛围灯（第三方接米家）接入调查

> 核对时间：2026-10-10
> 状态：**未接入，且"不通过米家控制它"已判定走不通。** 两轮探测都没找到任何本地接口，见第 8 节。

## 1 设备是什么

```text
类型      第三方设备，通过米家接入（不是小米自产）
配网热点  hzsj-light-wyra02_mibtF3E6，开放（无密码），信号 91~96%
命名含义  _mibt 后缀是小米系"蓝牙配网"的命名习惯（用 BLE 把 Wi-Fi 密码传给设备）
```

## 2 "第三方接米家"有两种实现，决定了能不能进 HA

```text
a) 走小米 MIoT 物模型   厂商按小米规范做，设备在米家云里有 MIoT spec
                        → 官方 xiaomi_home 集成能认，导入没问题
b) 只是米家里的插件     厂商用自己的云 + 米家挂一个 H5/RN 插件页面，
                        设备不在小米的 MIoT 设备列表里
                        → 官方集成根本看不到它
```

目前还不知道这盏灯是哪种。区分方法：配网后在米家里看设备信息页有没有 MIoT 型号/urn，或者直接试导入。

## 3 配网为什么绕不开米家（有证据）

装了 `python-miio` 看它的命令表：`miiocli` 的命令全是**操作已配网设备**的
（airpurifier / yeelight / cloud / device / discover…），**没有任何配网命令**。
`cloud` 那个是拿设备列表和 token 的，前提是先登录小米账号。

小米系的配网是"设备热点或蓝牙 + 账号加密握手"，没有公开实现 → 公开工具只能处理
"已经在网上、已经有 token"的设备。所以配网只能用米家 App（或厂商自己的 App）。

## 4 探设备热点的那一轮（2026-10-10）

做法：给那个开放热点建了个手动 Wi-Fi 配置文件（`_work\xiaomi\ap_profile.xml`），连上去探。

```text
连接结果   成功，DHCP 拿到 192.168.99.2 → 设备热点网段是 192.168.99.x
ARP        192.168.99.1 不应答（邻居项 Unreachable、MAC 全零）
端口扫描   80 / 443 / 8080 / 8443 / 6668 / 6667 全部关闭
           其中 6668 是涂鸦的本地协议端口 → 说明它不是涂鸦系
HTTP       没有任何网页响应 → 没有本地配置页
```

两个干扰因素，导致这轮探得不彻底：

```text
Windows 在约 30 秒后自动切回 pearcat（设备热点没有外网，Windows 会挑有外网的连）
随后设备的 AP 从扫描里消失 → 它退出了配网模式
```

判断：**大概率就是小米自家的加密配网，没有对外的本地接口**；但因为设备连 ARP 都没应答
（L2 通、IP 层不通），不能 100% 排除"有本地接口只是需要特定访问方式"。

## 5 下一轮要更彻底的话（需要配合）

```text
1 让设备重新进配网模式（长按开关键几秒，或断电重上电）
2 先把 pearcat 的 profile 临时改成手动，防止 Windows 抢回去：
     netsh wlan set profileparameter name="pearcat" connectionmode=manual
3 连上设备热点后立刻：抓 DHCP 网关 → ping → 按网段扫活跃主机
   → miIO 发现（_work\xiaomi\probe_lan.py）→ SSDP
4 完事恢复：
     netsh wlan set profileparameter name="pearcat" connectionmode=auto
     netsh wlan connect name="pearcat"
     删掉临时配置文件（netsh wlan delete profile name="hzsj-light-wyra02_mibtF3E6"）
```

## 6 更省事的那条路

```text
米家 App 配网（用一次）→ 官方集成导入（我这边工具已就绪：
_work\ha\xiaomi_options.py，第一步表单里正好有 update_devices）
→ 如果它是 a 类，灯会自动出现在 HA 里并拿到 set_brightness
→ 如果它是 b 类，导入时会看不到它，那时候再考虑厂商 App 那条线
```

## 7 现场遗留

```text
本机多了一个 Wi-Fi 配置文件 hzsj-light-wyra02_mibtF3E6（手动模式，不会自动连）
不用了就删：netsh wlan delete profile name="hzsj-light-wyra02_mibtF3E6"
```

## 8 第二轮探测（2026-10-10）与最终判断

按第 5 节的做法重跑了一遍，脚本在 `_work\xiaomi\switch_and_probe.ps1`（先把 pearcat 设成手动，
防 Windows 抢回；探完自动恢复）。这次 ARP 通了，探测结果才有意义：

```text
设备地址   192.168.99.1，MAC 9a-e0-81-ee-f3-e6 —— 就是这个热点的 BSSID，L2/IP 都可达
TCP 扫描   整个 192.168.99.0/24 扫 10 个 IoT 常用端口（80/443/81/8080/8443/54321/6668/9999/22/23）
           → 一台开放端口的主机都没有
miIO 发现  （224.0.0.50:54321）无应答
涂鸦发现   （广播 6666 / 6667）无应答
SSDP       无应答
mDNS       无应答
HTTP 首页  没有可用主机
```

**结论：这盏灯没有任何对外的本地接口。** 它只认小米那套加密配网协议，而这套协议
没有公开实现（第 3 节的证据：`miiocli` 连配网命令都没有）。

所以用户的目标——**"不通过米家，在 HA 里控制它"——在当前设备上做不到**，
不是配置问题，是设备压根没提供本地入口。

剩下的选择：

```text
① 米家配一次网 → 官方集成导入（工具已就绪：_work\ha\xiaomi_options.py）
   注意：如果它是第 2 节里的 b 类（米家插件型第三方），官方集成可能看不到它，
   配网后试一次就知道
② 换一盏支持 Matter 的灯 —— HA 内置 matter 集成，HA 自己当 controller，
   配网和控制全程不碰任何厂商云，这是唯一真正"不通过米家"的路
```

## 9 两次都踩到的坑（值得记）

```text
PowerShell 里 $home 是只读内置变量，不能拿来当自己的变量名。
第一轮脚本用了 $home，赋值静默失败，导致"恢复网络"那步没执行，
机器一直挂在设备热点上。变量名已改成 $homeSsid。

设备热点没有外网时，Windows 会自动切回有外网的那个 Wi-Fi，
所以探测前必须先把家用 profile 设成手动连接。
```
