# 05：Zigbee 在当前部署下的判断（对 17 号文档的补充）

> 核对时间：2026-10-10
> 依据：`finally new paper\HomeAssistant双仓库接口分析\17_Zigbee接入本机HA的可行性分析.md`（2026-09-28）
> 加一条它当时不知道的事实，结论会变。

## 1 17 号文档讲了什么

它回答的是"USB 棒能不能插进这台机器的 HA 容器"，结论准确且仍然成立：

```text
Docker Desktop 不做 USB 直通 → 容器里没有 /dev/tty*、没有 /dev/serial
所以"棒直接插主机 → HA 容器"这条路走不通
可行路线：① 厂商网关 + XiaomiGateway3   ② 网络协调器 SLZB-06 + ZHA socket://
         ③ USB 棒 + Windows 侧 Z2M     ④/⑤ USB 棒 + usbipd 进 Docker/WSL2
```

本机实测复核：**没有任何 Zigbee 硬件**（`Get-PnpDevice` 里只有蓝牙虚拟串口 COM3~COM6，没有 CH340/CP210x/FTDI 之类的 USB 桥），HA 里 `zha` 集成是有的（内置）。

## 2 17 号文档没算到的一条约束

Zigbee 设备说 802.15.4，**不说 IP**，所以它们必须通过一个"协调器"（USB 棒 / 网络协调器 / 厂商网关）中转。于是有两条独立约束：

```text
约束 A（17 号文档讲的）  协调器要有通路到 HA：USB 直通 / socket:// / MQTT 都不缺
约束 B（10-10 才查明）   协调器必须和设备在同一无线电范围内——也就是必须放在家里，
                        而且 HA 还要能通过网络够到它
```

约束 B 的依据（见 `03_层三米家接入.md` 第 6 节）：

```text
本机 WLAN  = tjuwlan（校园网），172.18.147.97，同网段只有网关
设备所在   = pearcat（家里），集成缓存里 local_ip = null
```

## 3 所以在当前部署下，各条路的实际可行性

| 路线 | 现在能走通吗 | 原因 |
| --- | --- | --- |
| USB 棒插这台笔记本 | ✗ | 无线电覆盖不到家里的设备（约束 B） |
| USB 棒 + usbipd 进容器 | ✗ | 同上；而且还要先解决约束 A |
| 网络协调器 SLZB-06 + ZHA `socket://` | ✗ | 协调器得放家里；校园网够不到家用网络，而且 HA 官方明确不建议串口代理走 WAN/VPN |
| 厂商网关 + XiaomiGateway3（局域网直连） | ✗ | XiaomiGateway3 走局域网，要求 HA 和网关同一网段 |
| **Zigbee 子设备挂在米家网关下 → 已装的官方 xiaomi_home 集成** | **✓** | 走**云**，和氛围灯同一条路，不需要任何新硬件 |

最后一条是当前唯一能立刻走通的：如果这些 Zigbee 设备是挂在米家网关（比如多模网关）下面的子设备，那它们在米家云端就是普通设备，官方集成导入时一并带进来——代价还是云延迟。

注意区分：**同一个米家多模网关**，用 XiaomiGateway3 是局域网直连（快，但要同网段），用官方 xiaomi_home 集成是云（慢，但跨网络可用）。当前部署只能用后者。

## 4 想真正把 Zigbee 做成本地

还是那句：**把跑 HA 的机器搬到设备所在的网络**（家里的小主机/树莓派，见 20 号文档）。
那时约束 B 消失，17 号文档里的路线 ①②③ 就都成立了，`zha` 是 HA 内置，配一下就能用。

## 5 结论

```text
现在（HA 在校园网）  只能走云：Zigbee 子设备挂米家网关 → 官方集成导入
搬回家（HA 在 pearcat） USB 棒/网络协调器/网关局域网直连 三条路任选
```
