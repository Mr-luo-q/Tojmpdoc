## 2 卡住的地方：`homeassistant.local` 解析不了

上游把 OAuth 回跳地址**写死在源码里**，而且下拉框只给这一个选项：

```python
# custom_components/xiaomi_home/const.py:142
OAUTH_REDIRECT_URL: str = 'http://homeassistant.local:8123'
```

登录最后一步，小米会把浏览器重定向到
`http://homeassistant.local:8123/api/webhook/<一个随机 id>?code=...&state=...`，
而这个页面由 HA 自己提供、负责把授权码交回 config flow。

本机实测：`Resolve-DnsName homeassistant.local` 解析失败，连不上 8123。
（HA 容器名叫 `homeassistant`，但 Docker Desktop 不会把这个名字注册到宿主的 DNS。
容器里的 mDNS 广播也过不了 Docker 的虚拟网络到宿主网卡。）

**解法**：往 Windows 的 hosts 加一条。已经在非提权会话里验证过，HA 不校验 Host 头
（带 `Host: homeassistant.local:8123` 请求返回 200），所以这一条就够了。

```powershell
# 需要「以管理员身份运行」的 PowerShell
Add-Content -Path 'C:\Windows\System32\drivers\etc\hosts' -Value '127.0.0.1 homeassistant.local'
Resolve-DnsName homeassistant.local   # 应返回 127.0.0.1
```

撤销：用管理员权限打开 `C:\Windows\System32\drivers\etc\hosts`，删掉那一行即可。

### 两种稳定解法（都不用每次手工改地址）

回跳页 `miot/resource/oauth_redirect_page.html` 其实是个**静态页**：它不做任何回传，
授权码是 HA 后端从 URL 的 `?code=` 里直接取走的（`_handle_oauth_webhook` 写进
`fut_oauth_code`，再由 `__check_oauth_async` 取走）。所以只需要浏览器能对
`homeassistant.local` 发出这个 GET 就够了。两条路：

**A 不动系统文件（已验证）**：跑 `_work\ha_login.cmd`，用带
`--host-resolver-rules="MAP homeassistant.local 127.0.0.1"` 的独立 profile 打开 HA。
Edge 和 Chrome 都是 Chromium 内核、都支持这个参数，**两个都实测过**：带参数能打开
`http://homeassistant.local:8123`，不带则报 `ERR_NAME_NOT_RESOLVED`。
脚本优先用 Edge（用户实际使用），找不到再退到 Chrome。
**必须用独立 profile**——浏览器已经在运行时，新起的进程只会把 URL 转给已有进程，
命令行参数会被丢掉。

**B 全局永久**：跑 `_work\fix_hosts.cmd`，双击后点一下 UAC 的"是"，往 hosts 加
`127.0.0.1 homeassistant.local`。对所有浏览器和程序生效，重启不丢。

### 一个容易踩的坑

**登录进行中不要重启 HA。** config flow 里的 `__check_oauth_async` 会一直等那个授权码
（代码里看不到超时），重启容器会把这个待处理流程直接杀掉。日志里表现为
`Task <...XiaomiMihomeConfigFlow.__check_oauth_async()...> was still running after final writes`，
从界面上看就是"卡住了、怎么弄都不成功"。

## 4c 那个网络报错的结论

首次登录时日志里有：

```text
update spec std lib error, retry, 0/1/2, <urlopen error [Errno 101] Network unreachable>
load spec std lib failed
get manufacturer info failed → load manufacturer data failed
```

**是启动瞬间的抖动，不是配置问题。** 证据：容器内直接请求
`https://miot-spec.org/miot-spec-v2/template/list/device` 返回 200；重启 HA 后不再复现；
spec 库已经落盘缓存（`.storage\xiaomi_home\miot_specs\spec_std_lib.dict`，762 KB，
上游 `SPEC_STD_LIB_EFFECTIVE_TIME` 是 14 天）。Errno 101 通常是 IPv6 无路由时的表现，
这台机器的 IPv6 确实不通（Docker 拉镜像时也撞过同一个问题）。

## 5 注意

- **安全**：上游 README 明确说明，登录后小米账号的设备信息、证书、令牌会**明文**保存在 HA 配置目录里。
  这台是沙盒 HA（`D:\homeassistant-sandbox`），配置目录不要外传；怀疑泄漏可以在小米账号里撤销授权。
- **本地模式需要小米中枢网关**（固件 3.3.0_0023 以上），没有的话所有控制命令都走小米云。
  文档里记的"云端写入偶尔 >10 s""`verified=false` 别当成功"都是这个原因。
- 上游不支持蓝牙设备、红外设备和虚拟设备。
- 区域数据是隔离的，选错区域会看不到设备。

## 6 本地化的天花板：设备根本不在同一个局域网（2026-10-10 实测）

想"不走米家云、本地直连"的前提是跑 HA 的机器和设备在同一局域网。实测下来**不是**：

```text
本机 WLAN        SSID = tjuwlan（校园网），IP 172.18.147.97，网关 172.18.128.1
邻居表           同一网段只有网关一台设备（没有任何其他主机/设备）
冰箱记录的 SSID  pearcat，且 local_ip = null（集成当时也判断出够不着）
miIO 局域网发现  发 224.0.0.50:54321 的 hello 包，6 秒内 0 台设备应答
```

也就是说：**冰箱（以及米家账号里其他设备）在家里那张 `pearcat` 网络上，而这台笔记本在
校园网 `tjuwlan` 上**。所以本地直连不是"配置没做对"，是物理上够不着。

由此得到的判断：

```text
HA 自带 xiaomi_miio（只走本地 miIO）   不可用——需要一个能 ping 通的设备 IP
HA 自带 yeelight（局域网发现）          不可用——需要同网段
al-one/hass-xiaomi-miot（社区集成）     能装，也是云+本地双通道，本地不可达时照样落回云
官方 XiaoMi/ha_xiaomi_home（在用）      ctrl_mode=auto 已经会优先本地，够不着就自动走云
DIY MQTT 桥                            桥自己也得走云 API，只是换个客户端，不是"不走米家"
```

所以换集成可以换，但**换不掉云**。真要本地化，得让 HA 和设备在同一网络——
比如把 HA 放到家里的小主机/树莓派上（参见 `finally new paper\HomeAssistant双仓库接口分析\20_树莓派部署HA的方案与本项目用法.md`），
那时官方集成的 `ctrl_mode: auto` 会自动切到本地通道。

探测脚本：`_work\xiaomi\probe_lan.py`（只发发现包，不改设备状态）。
